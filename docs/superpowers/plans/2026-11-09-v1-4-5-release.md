# v1.4.5 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the merged role-permission consistency work as Asterisk Panel v1.4.5.

**Architecture:** Update the single application version source and its release smoke assertion, verify the full repository, then use the established annotated-tag and GitHub Release flow. Publication must leave `HEAD`, `origin/main`, tag, and release target on one commit.

**Tech Stack:** PHP, Git, GitHub CLI, Bash verification.

**Spec:** `docs/superpowers/specs/2026-11-09-v1-4-5-release-design.md`

## Global Constraints

- Version is exactly `1.4.5`; tag is exactly `v1.4.5`.
- Never move or overwrite an existing tag or GitHub Release.
- Add no product behavior and perform no production deployment.
- Publish only after the full verification suite passes.

## Review Focus

- Duplicate release name: local tag, remote tag, and GitHub Release must all be absent before creation; pinned by preflight checks.
- Version drift: app config and release smoke must both say `1.4.5`; pinned by `tests/release-version-smoke.php`.
- Unverified artifact: the tag must be created only after PHP, smoke, Bash, and diff checks pass.
- Commit mismatch: local `HEAD`, `origin/main`, dereferenced tag, remote tag, and release target must match after publication.
- Accidental deployment: release commands must not invoke the production updater.
