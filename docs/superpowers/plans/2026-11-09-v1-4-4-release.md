# v1.4.4 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the merged Material audio player and tenant-timezone fixes as Asterisk Panel v1.4.4.

**Architecture:** Update the single application version source, pin it with a smoke test, verify the complete tree, then publish through the existing Git/GitHub annotated-tag release flow. No production deployment runs as part of this plan.

**Tech Stack:** PHP smoke tests, Git, GitHub CLI.

**Spec:** `docs/superpowers/specs/2026-11-09-v1-4-4-release-design.md`

## Global Constraints

- Release version is exactly `1.4.4`; tag is exactly `v1.4.4`.
- Patch release only; no additional product features.
- Do not run the production updater.
- Do not convert existing WAV recordings.
- Never move or overwrite an existing `v1.4.4` tag/release; stop if one exists.

## Review Focus

- Version mismatch: config, test, tag, and GitHub Release must all say `1.4.4`; pinned by the release smoke test and remote verification.
- Dirty publish: tag must point to the verified clean `main` commit; pinned by status and SHA checks before push.
- Partial publication: both `main` and annotated tag must reach origin before creating the GitHub Release; pinned by remote-ref checks.
- Duplicate release: preflight must prove no local/remote tag or GitHub Release already exists.
- Accidental deployment: no updater or server command is part of any step.
